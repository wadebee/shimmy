Use the data-processing tools according to the input format: `jq` for JSON streams, `yq` for YAML-oriented expressions and format conversion, `jv` for JSON Schema validation against JSON or YAML instances, and `rg` for recursive source-tree or text search ([guide.md:10-22](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/jq/guide.md#L10-L22), [guide.md:19-33](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/yq/guide.md#L19-L33), [guide.md:10-20](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/jv/guide.md#L10-L20), [guide.md:10-23](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/rg/guide.md#L10-L23)).

For language and project automation, `go` supplies the compiler and standard development commands, `npx` executes npm package binaries without requiring host Node.js, `task` runs `Taskfile.yml` automation, and `bats` executes shell behavioral tests ([guide.md:14-23](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/go/guide.md#L14-L23), [guide.md:11-15](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/npx/guide.md#L11-L15), [guide.md:10-21](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/task/guide.md#L10-L21), [guide.md:11-23](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/bats/guide.md#L11-L23)).

`gh` covers GitHub workflows and persists its CLI configuration through a host-mounted config directory; `skopeo` works directly with image registries and OCI transports; `tessl` manages agent skills and context packages; and `textual` supplies the developer CLI for running, serving, and diagnosing Textual applications ([guide.md:9-15](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/gh/guide.md#L9-L15), [guide.md:29-35](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/gh/guide.md#L29-L35), [guide.md:12-26](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/skopeo/guide.md#L12-L26), [guide.md:13-27](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/tessl/guide.md#L13-L27), [guide.md:14-22](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/textual/guide.md#L14-L22)).

## Cloud and Cluster Tools

`aws` and `gcloud` expose the main service-oriented CLIs for AWS and Google Cloud. The AWS wrapper mounts `~/.aws` read-only and forwards `AWS_*`; the Google Cloud wrapper persists the selected Cloud SDK configuration directory read-write and may mount the host kubeconfig read-only ([guide.md:33-49](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/aws/guide.md#L33-L49), [guide.md:38-54](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/gcloud/guide.md#L38-L54)).

For Kubernetes and OpenShift, `flux` is the GitOps client and `oc` is the OpenShift CLI. Flux does not automatically mount `$HOME/.kube`; an exact kubeconfig can be mounted read-only with `SHIMMY_FLUX_KUBECONFIG`. The `oc` wrapper also does not automatically mount `$HOME/.kube`, but it forwards `KUBECONFIG` when set and lets callers select retained tracks with `SHIMMY_OC_VERSION` ([guide.md:40-51](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/flux/guide.md#L40-L51), [guide.md:18-27](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/oc/guide.md#L18-L27), [guide.md:29-38](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/oc/guide.md#L29-L38)).

`community-ansible-dev-tools` is a multi-command Ansible execution environment, not a single executable; it exposes project files at `/workdir` and can mount a different absolute work directory explicitly. `terraform` supplies the normal plan/apply/state workflow, mounts `~/.aws` read-only when present, and forwards `AWS_*` and `TF_VAR_*` into its runtime ([guide.md:20-34](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/community-ansible-dev-tools/guide.md#L20-L34), [guide.md:14-24](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/terraform/guide.md#L14-L24), [guide.md:41-52](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/terraform/guide.md#L41-L52)).

Treat mutating cloud and cluster commands as external changes. Flux specifically calls out bootstrap, reconcile, suspend, resume, create, delete, and uninstall operations and notes that provider tokens can be written into Kubernetes Secrets ([guide.md:16-20](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/flux/guide.md#L16-L20)). Terraform distinguishes non-mutating validation and planning from `apply`, `destroy`, and direct state operations ([guide.md:14-24](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/terraform/guide.md#L14-L24)).

## Network and Operations Tools

For direct network work, use `netcat` for targeted TCP, UDP, TLS, listener, or proxy activity and `nmap` for discovery and scanning. Containerized Nmap can see a different network perspective than a native host process, especially through rootless Podman or the macOS Podman VM; host networking, raw capabilities, Nmap privileged mode, and Podman privileged mode are all explicit opt-ins rather than defaults ([guide.md:10-22](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/netcat/guide.md#L10-L22), [guide.md:32-41](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/nmap/guide.md#L32-L41), [guide.md:52-56](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/nmap/guide.md#L52-L56)).

The two OPNsense MCP tools have deliberately different authority. `opnsense-mcp-read-only` is the default for inventory, diagnostics, inspection, and review. `opnsense-mcp-admin` is reserved for explicit configuration changes, approved change windows, or capabilities unavailable from the read-only server; a read-only privilege error is not a reason to switch automatically to admin ([guide.md:10-22](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/opnsense-mcp-read-only/guide.md#L10-L22), [guide.md:9-23](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/opnsense-mcp-admin/guide.md#L9-L23)). Both are stdio MCP servers that require OPNsense API configuration before connecting ([guide.md:16-22](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/opnsense-mcp-read-only/guide.md#L16-L22), [guide.md:15-21](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/opnsense-mcp-admin/guide.md#L15-L21)).

Other operations-oriented packages cover different resources: `gdrive` is an OAuth-backed stdio MCP server for Drive and Sheets; `keepassxc` exposes password-database inspection and modification; `skopeo` works with remote registries and OCI storage; and `logmine` is a locally built gologmine wrapper whose retained guide currently exposes a help-first entrypoint ([guide.md:10-20](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/gdrive/guide.md#L10-L20), [guide.md:10-22](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/keepassxc/guide.md#L10-L22), [guide.md:12-26](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/skopeo/guide.md#L12-L26), [guide.md:3-16](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/logmine/guide.md#L3-L16)).

## Choosing and Using a Tool Safely

Start with the tool's `guide.md`, then verify the intended profile selection before invoking the host-visible command. Profiles own their direct `bin/<tool>` wrappers and concrete-version assets; selectors use `tool` or `tool@version`, and exact first selections record pinned policy while unqualified selections record tracking policy ([README.md:278-291](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/README.md#L278-L291)).

The following boundaries vary by tool and should be reviewed explicitly:

| Boundary | What to check |
|---|---|
| Filesystem | Most tools mount `$PWD` at `/work`, but exceptions exist: Ansible uses `/workdir`, while logmine mounts both `$PWD` at the same absolute path and at `/work` ([guide.md:29-34](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/community-ansible-dev-tools/guide.md#L29-L34), [guide.md:36-40](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/logmine/guide.md#L36-L40)). |
| Credentials and configuration | AWS mounts `~/.aws` read-only; Google Cloud and GitHub persist dedicated config directories read-write; gdrive needs OAuth client values and a credential directory ([guide.md:40-49](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/aws/guide.md#L40-L49), [guide.md:49-60](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/gcloud/guide.md#L49-L60), [guide.md:26-35](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/gh/guide.md#L26-L35), [guide.md:37-55](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/gdrive/guide.md#L37-L55)). |
| Secrets | Skopeo accepts a Podman secret containing registry `auth.json`; the OPNsense admin guide requires separate admin API-key and API-secret Podman secrets ([guide.md:36-42](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/skopeo/guide.md#L36-L42), [guide.md:51-55](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/opnsense-mcp-admin/guide.md#L51-L55)). |
| Host CA trust | CA-aware tools opt in through one absolute readable file named by `SHIMMY_HOST_CA_BUNDLE`; the runtime mounts the exact file read-only and maps it to the tool's native CA variable. Replacement-style trust variables may require a combined public-and-private bundle ([README.md:43-69](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/README.md#L43-L69)). |
| Network and privilege | Nmap's host networking, raw capabilities, and privileged modes require explicit environment opt-ins, and macOS Podman VM networking may not match native-host visibility ([guide.md:32-41](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/nmap/guide.md#L32-L41), [guide.md:52-56](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/nmap/guide.md#L52-L56)). |
| Mutation | Review external targets before Flux reconciliation, Terraform apply/destroy, Skopeo copy/delete/sync, password-database writes, or the admin OPNsense server ([guide.md:16-20](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/flux/guide.md#L16-L20), [guide.md:16-24](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/terraform/guide.md#L16-L24), [guide.md:19-26](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/skopeo/guide.md#L19-L26), [guide.md:20-22](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/keepassxc/guide.md#L20-L22), [guide.md:9-23](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/opnsense-mcp-admin/guide.md#L9-L23)). |

Image overrides and pull/build controls are tool-specific and are documented in each guide. They consistently use `SHIMMY_`-prefixed wrapper settings, while upstream-standard configuration variables such as `AWS_*`, `GH_*`, `CLOUDSDK_CONFIG`, and `TF_VAR_*` retain their upstream names where the wrapper explicitly supports them ([guide.md:33-49](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/aws/guide.md#L33-L49), [guide.md:17-27](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/gh/guide.md#L17-L27), [guide.md:38-44](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/gcloud/guide.md#L38-L44), [guide.md:34-52](https://github.com/wadebee/shimmy/blob/aaebadedc4bd1ac9f56f7e31bd394ae86cd97485/tools/terraform/guide.md#L34-L52)).
