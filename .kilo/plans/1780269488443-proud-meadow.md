# Shimmy Shim Plan: gdrive

## Tool Information
- **Tool Name**: gdrive
- **Container Image**: docker.io/mcp/gdrive
- **Repository**: https://github.com/isaacphi/mcp-gdrive
- **Description**: MCP server for interacting with Google Drive and Sheets

## Implementation Approach
Since the tool is already available as a container image (`mcp/gdrive` on Docker Hub), we will create a standard shimmy wrapper that executes `podman run` with the appropriate configuration.

## Required Files to Create/Modify
1. `shims/gdrive` - Runtime shim wrapper
2. `shims/gdrive.conf` - Shim configuration
3. Update `scripts/install-shimmy.sh` to include the new shim
4. Update `scripts/test-shimmy.sh` to add tests for the new shim
5. Update `README.md` to document the new shim

## Shim Configuration Details
Based on the Docker Hub information and the original repository:

### Environment Variables Needed
- `CLIENT_ID` - OAuth Client ID from Google Cloud
- `CLIENT_SECRET` - OAuth Client Secret from Google Cloud  
- `GDRIVE_CREDS_DIR` - Directory for OAuth credentials (defaults to user config)
- May need `GDRIVE_OAUTH_PATH` and `GDRIVE_CREDENTIALS_PATH` for container usage

### Volume Mounts Needed
- OAuth keys file: `-v /path/to/gcp-oauth.keys.json:/gcp-oauth.keys.json`
- Credentials storage: `-v mcp-gdrive:/gdrive-server` (as shown in Docker Hub examples)
- Current working directory: `-v "$PWD:/work"`

### Execution Mode
The tool appears to be a server/MCP service, but based on the usage examples, it can be run in different modes:
- `auth` mode for authentication
- Standard mode for serving MCP requests
- For a CLI shim, we'll likely want to support passing through commands/arguments

## Implementation Steps

### 1. Create runtime shim (`shims/gdrive`)
```sh
#!/bin/sh
set -eu

SCRIPT_DIR=$(cd -- "$(dirname -- "$0")" && pwd)
SHIMMY_PODMAN_HELPER_FILE=$SCRIPT_DIR/../lib/shims/shimmy-podman.sh

SHIMMY_GDRIVE_IMAGE=${SHIMMY_GDRIVE_IMAGE:-docker.io/mcp/gdrive:latest}
SHIMMY_GDRIVE_IMAGE_PULL=${SHIMMY_GDRIVE_IMAGE_PULL:-}

if [ ! -f "$SHIMMY_PODMAN_HELPER_FILE" ]; then
  printf 'ERROR: missing shim helper: %s\n' "$SHIMMY_PODMAN_HELPER_FILE" >&2
  exit 1
fi

# shellcheck source=lib/shims/shimmy-podman.sh
. "$SHIMMY_PODMAN_HELPER_FILE"

shimmy_podman_preflight_require "the gdrive shim"

if [ "$SHIMMY_GDRIVE_IMAGE_PULL" = "always" ]; then
  SHIMMY_GDRIVE_PULL_ARG=--pull=always
fi

exec "$SHIMMY_PODMAN_BIN" run --rm -i \
  --platform "$SHIMMY_PODMAN_PLATFORM" \
  ${SHIMMY_GDRIVE_PULL_ARG:+"$SHIMMY_GDRIVE_PULL_ARG"} \
  -v "$PWD:/work" \
  -w /work \
  "$SHIMMY_GDRIVE_IMAGE" \
  "$@"
```

### 2. Create configuration file (`shims/gdrive.conf`)
```
shim_config_version=1
shim_name=gdrive
smoke_arg=--help
```

### 3. Update installer (`scripts/install-shimmy.sh`)
Add "gdrive" to the list of shims to install.

### 4. Update tests (`scripts/test-shimmy.sh`)
Add a test case for gdrive that runs a non-mutating command like `--help`.

### 5. Update documentation (`README.md`)
Add entry to the "Included Shims" table.

## Validation Approach
1. Verify the shim executes correctly with `gdrive --help` or similar
2. Check that environment variables can be overridden
3. Confirm volume mounts work as expected
4. Test that the shim follows all shimmy conventions

## Dependencies
- Podman must be installed and accessible
- User must have Google Cloud OAuth credentials set up

## Notes
The gdrive tool requires authentication setup before first use, which involves:
1. Creating a Google Cloud project
2. Enabling Google Drive API and Google Sheets API
3. Setting up OAuth consent screen
4. Creating OAuth Client ID
5. Downloading and configuring the OAuth keys

This authentication process is outside the scope of the shim but should be documented in the README.
